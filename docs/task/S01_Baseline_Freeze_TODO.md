只解决基线可追溯这一项工程事实：为当前源码、已有可执行程序、关键输入和现有性能证据建立可校验快照，供后续 V2 与 legacy A/B 比较。

## 数学约束

不改变任何离散方程、材料参数、网格、时间步、求解或物理验收容限。历史 legacy 结果仅作为 baseline 证据，不视作 V2 数值 gate 通过。

## 验收

- **T0：** 源码/程序/输入清单完整；archive 可读取；构建类型、编译器、依赖和 Git 状态有证据，未知项写 `unavailable`；原始二进制先于验证保存；执行现有构建检查并记录结果。
- **T1：** 清单逐文件 SHA-256 与 archive 内容一致；输入与 production 源文件任务前后哈希一致；选定现有 operator/contract 检查可执行且结果如实记录。
- **T2：** 至少一项短运行或现有短 contract 的新计时；冻结三模块代表性输入和已有性能证据。历史结果与新测量不得混用，S01 通过不代表各模块数值验收通过。

## 失败规则

- 缺失原始程序、无法读取源码/关键输入、缺少必要构建依赖且无法在本任务范围完成验证时记 `BLOCKED` 并说明缺项。
- 哈希不一致、归档遗漏、验证过程污染原始输入/源码时记 `FAIL`；修复归档流程后重新验收，不修改数值方法以迁就结果。
- 已存在的数值失败如实冻结为基线已知问题，不隐瞒、不修改容限，不据此扩大任务。
